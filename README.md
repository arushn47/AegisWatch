# 🛡️ AegisWatch

> **Real-Time Global Natural Disaster Intelligence, Alert & Emergency Assistance Platform**
> *Final Year Capstone Project (Engineering & Computer Science)*

---

## 🌟 Overview

AegisWatch aggregates fragmented global natural hazard data into a unified, high-contrast mission-control situational dashboard. It pairs **deterministic notification rules in Supabase** (per-user alert preferences matched against live ingested events, streamed in-app over Realtime) with a live multi-feed radar map. Advisory text on incidents is deterministic — the app does not call any AI model today.

* **Core Principle:** *"Data and deterministic rules detect risk. AI explains the situation and assists the user."* (The deterministic layer is the Supabase notification trigger + alert-preference matching; AI guidance was in the original roadmap but is not built — see the reconciliation note in [docs/PRD.md](docs/PRD.md).)

---

## 🚀 Current Live Features

* **Interactive Tactical Situational Radar**: High-contrast ESRI World Dark Gray basemap with real-time pulsing beacon markers and zero watermarks.
* **Live Real-Time Multi-Feed Telemetry (no static fixtures)**:
  - **USGS** — global earthquakes (M2.5+, past 24h) + Indian subcontinent / Himalayan belt significant quakes (M4.5+, past 7 days).
  - **NASA EONET** — open natural events (wildfires, storms, floods, volcanoes, landslides, temperature extremes, drought, snow).
  - **GDACS** (UN/EC) — tropical cyclones, floods, droughts with alert levels + affected countries. **Primary India coverage source.**
  - **NOAA/NWS tsunami advisories** — NTWC Palmer + PTWC Honolulu, proxied through `/api/tsunami`, parsed client-side. Only Warning/Advisory/Watch emitted.
  - **ReliefWeb (UN OCHA)** — opt-in, requires approved `NEXT_PUBLIC_RELIEFWEB_APPNAME`.
* **Supabase Auth**: email signup (with optional avatar URL) + Google OAuth + email login + password reset. Session refresh via the App Router middleware (`proxy.ts`), which also protects `/settings`.
* **Database-backed notification center + Realtime**: notifications are generated by the `fn_notify_disaster_event()` trigger when a new/updated event matches a user's `alert_preferences`, then streamed in-app over the `supabase_realtime` publication.
* **User profile + settings (DB-backed)**: `full_name` and `avatar_url` stored in `user_profiles`; delivery flags stored in `alert_preferences`. Avatar captured on email signup (optional URL), automatically from Google OAuth, and editable in both the Profile Modal and Settings.
* **India region coverage (live, honest)**: the "South Asia · India" view uses country tags (ISO `IND`/`IN`, authoritative) plus a tightened coordinate fallback box (lat 6.5–35.7°N, lng 68.1–97.4°E). Afghanistan and China are excluded. If no live feed has an India event, the panel is honestly empty.
* **Signup works end-to-end**: the broken `fn_handle_new_user` trigger was replaced (see [supabase/fix-signup.sql](supabase/fix-signup.sql)) with a version that cannot abort the auth transaction.
* **Design Parity**: Built strictly against the team's Stitch **Orbital Telemetry & Crisis Operations** design tokens.

## 🛠️ Technology Stack

* **Frontend**: Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS + Leaflet
* **Auth / DB / Realtime**: Supabase (managed PostgreSQL + Auth + Realtime + Storage-ready)
* **Map Engine**: Leaflet + ESRI World Dark Gray Canvas
* **Live Ingestion**: USGS, NASA EONET, GDACS, NOAA/NWS tsunami (via `/api/tsunami` proxy), optionally ReliefWeb
* **Backend (original roadmap — NOT the live runtime)**: the original plan described Java 21 + Spring Boot 3.x + PostgreSQL + PostGIS + Redis. The project's actual backend converged on Supabase. See [docs/Architecture.md](docs/Architecture.md) and the reconciliation note in [docs/PRD.md](docs/PRD.md).

## 🏃 Quick Start (Run Locally)

### 1. Clone the repository

```bash
git clone https://github.com/arushn47/DisasterWatch.git
cd DisasterWatch
```

### 2. Configure Supabase (required)

The app cannot run without a Supabase project. Create one at [https://supabase.com](https://supabase.com), then:

1. Copy `frontend/.env.example` to `frontend/.env` (the real `.env` is git-ignored).
2. Fill in `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` from your project's API settings.
3. Add the `service_role` key as `SUPABASE_SERVICE_ROLE_KEY` (used by server-side actions / the schema-apply script).
4. Apply the schema: open [supabase/schema.sql](supabase/schema.sql) in your project's SQL Editor and run it. If signup is broken, also run [supabase/fix-signup.sql](supabase/fix-signup.sql).

### 3. Install & Start Frontend

```bash
cd frontend
npm install
npm run dev
```

### 4. Open in Browser

Visit **[http://localhost:3000](http://localhost:3000)** to view the live dashboard.
